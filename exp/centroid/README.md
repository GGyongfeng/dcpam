# 实验 B：圆心提取算法对方差的影响（★关键发现）

脚本：`exp/centroid/centroid.py`
运行：`uv run python exp/centroid/centroid.py`

## 背景

当前提取（`dcpam/steps/spot_extraction.py`）：峰值定位 → **局部窗口 ±30px 内**
强度加权重心，阈值 `centroid_threshold=0.3`。用户怀疑光斑不圆影响重心。

实测发现光斑不是小圆点，而是**大而饱和**：mask 约 4.5 万像素、4.3 万像素=255（纯饱和）、
半径约 120px、椭圆轴比均值仅 1.10（其实不太椭）。真正问题不是"椭圆"，是**饱和 + 拖尾**。

## 多算法对比（全体 172 组，全局阈值版）

| 提取法 | 平均 σ/μm |
|---|---|
| baseline(重心0.3) | 215.8 |
| 几何形心0.5 | 214.6 |
| **高阈值重心0.7** | **113.6** |
| 椭圆拟合0.5 | 176.9 |

椭圆轴比只 1.10 → 不圆不是主因，椭圆拟合反而不如高阈值重心。

## 隔离实验：窗口大小 × 阈值（找到真机理）

| 窗口 | 阈值 | σ/μm |
|---|---|---|
| 局部±30 | 0.3（**当前**） | 215.8 |
| 局部±30 | 0.8 | 210.5 |
| 全局 | 0.3 | 407.2（最差） |
| **全局** | **0.8** | **105.7** |
| 局部±150 | 0.8 | 105.9 |

**机理**：光斑半径~120px。
- 当前 ±30px 窗口**太小**，只框住中心饱和块 → 改阈值几乎无效（216→210）。
- 低阈值 0.3 把大片**不对称暗弱拖尾**纳入重心 → 中心被拉偏（全局+0.3 达 407）。
- **大窗口罩住整斑 + 高阈值(0.8)切掉拖尾**两者结合 → σ 腰斩至 **105.7μm**。

阈值扫描 0.8~0.85 是平坦最优区（非尖峰，不是过拟合）。

## 逐组验证（全局 0.9 vs 当前 0.3）：11 组 10 降，灾难组被治好

```
D90-0701 :1467.5 → 81.7  (↓1386)     D100-0701:1200.7 → 91.9  (↓1109)
D50-0701 : 348.6 → 53.6  (↓295)      D110-0701: 449.3 → 54.9  (↓394)

D200-0629: 219.2 →254.0  (↑35，唯一变差)  其余均降
```
baseline σ 上千的灾难组（低阈值重心被拖尾严重拉偏）全部被修复。

## 结论（本轮降方差最大收获）

**把圆心提取从「局部±30px + 阈值0.3」改为「大窗口(≥120px/全局) + 阈值≈0.8」，
平均 σ 从 215.8 → ~106μm，几乎腰斩（−51%）。** 远超几何自标定(−5%)与面偏移(负收益)。

这是可落地的代码改进（非过拟合、机理清晰、逐组稳健）：
- `spot_extraction.py`：`LOCAL_WINDOW_HALF` 30 → ~150（或自适应到光斑尺度），
  `centroid_threshold` 默认 0.3 → 0.8。
- 需注意：`SATURATION_CEIL` 等硬门槛和 quality 计算基于全局 mask，改窗口不影响它们；
  但要确认放大窗口不会把相邻干扰纳入（本数据集单光斑，安全）。

## 下一步建议
落地这个提取改进（改代码 + 重跑全 pipeline 验证 σ≈106），是当前性价比最高的降方差动作。
